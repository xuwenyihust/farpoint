# SO-101 v0.1.0 contract foundation

This document describes the reusable contracts introduced for the new SO-101
dataset lineage. It does not change the published `farpoint-so101` release spec
and it does not freeze a formal campaign before viewer and pilot evidence exist.

## Compatibility

- `farpoint.episode.v4` is the authoring contract for new campaign episodes.
- Existing v1/legacy normalization and v2/v3 validation remain available.
- LeRobot output remains Dataset v3; the Farpoint episode schema is an
  independent sidecar contract.

## Object model

`ObjectArchetype` describes geometry semantics and anchor conventions for
objects such as cubes, cylinders, meshes, or dolls. `ObjectVariant` binds an
archetype to dimensions, appearance, mass, and the object/table/gripper PhysX
materials. A variant field is reported as a variation axis only when the frozen
plan samples more than one value.

Each material records static friction, dynamic friction, restitution, friction
combine mode, and restitution combine mode. This avoids treating mass or
friction as an axis merely because it appears in metadata.

## Continuous positions

`FeasibleRegion` stores a versioned polygon produced by the workspace mapper
after object-footprint, whole-path IK, joint-limit, table/self-collision, and
camera-visibility checks. Placement is relative to an explicit object anchor.
The region generator freezes its own hash, constraint hash, and maximum
boundary clearance.

`ScrambledSobolSampler` samples continuously inside that polygon. Region labels
are derived from normalized boundary clearance rather than from a 5×5 grid:

- `outer`: clearance below one third
- `middle`: clearance from one third up to two thirds
- `core`: clearance of at least two thirds

A 5×5 or 7×7 grid may therefore be projected later by the Dashboard without
changing collection identity.

## Campaign identity

The campaign, every immutable continuation segment, and the append-only event
stream use independent schemas:

- `farpoint.collection-campaign.v1`
- `farpoint.collection-segment.v1`
- `farpoint.collection-event.v1`

Variation seeds bind object, yaw stratum, continuous position quota, region,
and split. Each variation derives exactly three attempt seeds. A deferred
variation receives a replacement seed in the same quota; it is never silently
mutated. Continuation segments require the parent manifest SHA256 and a new Git
commit.

`configs/workflows/so101_v010_self_healing.json` freezes the campaign-level
pause policy. The evaluator counts consecutive structural failures by distinct
variation rather than retry count, checks the last 50 attempts, two-hour success
liveness, the 60-second live heartbeat, the 500 GiB disk floor, and external
integrity errors. Failures are clustered by machine-readable class with three
distinct representative seeds. A terminal three-attempt failure produces a
deterministic replacement request with the same object, region, yaw, split, and
quota ordinal. `scripts/run_campaign_recovery.py` validates that a continuation
plan realizes those requests exactly before it freezes a segment bound to the
parent manifest hash.

The crossed quota builder has no robot-task-specific dimensions. For v0.1.0 it
is configured to yield 200 successes: 100 per object, 20 per object/yaw
stratum, core/middle/outer 5/10/5 per object/yaw, and train/validation 180/20.
There is no demonstration test split; evaluation scenes belong to a separate
holdout contract.

## Dual-camera requirement

Episode v4 requires exactly `observation.images.front` and
`observation.images.wrist`, both 640×480 at 30 Hz. Each camera records a config
version/hash, calibration, mount transform, and timestamp source. Recording
metadata asserts that both frames came from the same control tick. Frame-level
and MP4 validation is implemented in the collection/export stages, not inferred
from this metadata assertion.
