# SO-101 Dataset v0.2.0 collection runbook

v0.2.0 is a fresh 300-episode nominal baseline. It does not inherit nominal
or recovery episodes from v0.1.x. The frozen design crosses two paired cubes,
three target anchors, and five front-camera profiles. Within every one of the
30 cells, ten deterministic Latin-hypercube slots continuously vary cube X,
Y, and yaw; slot 9 is validation and slots 0–8 are train.

The versioned source is
`configs/variations/so101_v020_nominal300.json`. The completed candidate passed
the release gates and the owner-authorized release PR advances the dataset
specification to v0.2.0 at
`wenyixu101/so101-sim-oracle-pick-and-place`.

## Gates

1. Generate a 90×90 mm pad pilot with `create_so101_v020_plan.py pad-pilot`.
   It is valid only at 12/12 task success, settled footprint containment, and
   complete front/wrist evidence. If it fails, preserve the evidence and run
   exactly one 100×90 mm pad pilot. If that also fails, stop.
2. Generate the 30-cell combined pilot using the selected pad. It must obtain all 30/30 validated cell successes within at most 60 attempts,
   with no initial object/target overlap, structural errors, or camera evidence
   failures.
3. Run `authorize_so101_v020_pilots.py`. Formal plan creation fails closed
   unless the authorization binds the exact config and passed 12/12 and 30/30
   plan, manifest, and report hashes.
4. Generate and initialize the formal plan. Run only from the exact merged
   commit and pinned simulator image. The initial segment has 300 variations
   and a global 450-attempt ceiling.

Every pilot and formal report must request both cameras:

```text
scripts/report_so101_pilot.py ... --required-camera front --required-camera wrist
```

## Self-healing

The runtime watchdog stops a segment on five consecutive failures of the same
structural class, seven occurrences of one structural class in the most recent
ten attempts, an unreachable target, stale state, or structural evidence
failure. A stopped segment is diagnosed before continuation.

Write the immutable axis-stratified diagnosis before considering a repair:

```text
python scripts/diagnose_so101_v020_failures.py \
  --plan <segment-plan.json> --manifest <manifest.json> \
  --output <failure-diagnosis.json>
```

The report binds the plan and manifest and groups failures by class, 30-cell
identity, cube, target, camera, region band, and X/Y/yaw LHS strata.

Use the existing campaign recovery evaluator to build uncovered quota requests,
then `build_v020_continuation_plan` to materialize them. Carryovers preserve the
same variation and remaining attempt budget. Replacements change only the seed
and continuous jitter while preserving object/target/camera/split quota and the
original Latin-hypercube strata. Every continuation binds the parent manifest,
source plan, campaign, and frozen config hashes. Any target, camera, pad, or
sampling semantic change requires a new campaign and cannot inherit selection.

## Candidate

Aggregate only after the campaign has exactly one validated success for all
300 quotas. Export through the existing LeRobot v3 exporter, validate with the
repository validator under LeRobot 0.4.4, and record at least three successful
loader replays spanning different object/target/camera groups. Then run
`validate_so101_v020_candidate.py` with every segment plan. The report binds the
candidate tree SHA256 and fails on count, split, cell-balance, continuous-bound,
or LHS-stratum gaps.

HF upload, the immutable `v0.2.0` tag, Dataset Card, and Space changes require a
separate explicit owner authorization after candidate PASS.

## DGX cleanup

Generate a cleanup inventory with `create_cleanup_manifest.py`. Entries default
to retain and become disposable only when the input explicitly names the exact
path and reason. Releases, formal campaign evidence, published checksums, key
rollouts/ablations, released checkpoints, and Dashboard/Space dependencies are
protected. Before deleting any disposable entry, recheck tmux/process and all
references, verify the manifest hash, and record disk usage before and after.
